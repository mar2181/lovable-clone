### P0 — Dashboard `/dashboard` → 404 [PERSISTING ~72 days — since ~Jun 8]

**Live:** `curl https://hswebappbuilder.space/dashboard` → HTTP 404  
**Clerk headers:**
```
x-clerk-auth-reason: protect-rewrite, session-token-and-uat-missing
x-matched-path: /404
x-vercel-cache: HIT (age 675811s ≈ 7.8 days)
```

Root cause: `middleware.ts` calls `auth.protect()` with no redirect URL. When `NEXT_PUBLIC_DEV_BYPASS_AUTH=1` was cleared from Vercel env (as part of the Jun 8 security hardening), Clerk auth became active. Clerk's `protect()` without a configured sign-in URL performs a **rewrite** to `/404` instead of a redirect to `/sign-in`. The route exists and builds correctly; this is a Clerk config gap, not a missing route.

**Sign-in page: 200 ✅** — the destination already works.

**Fix (repo edit or Vercel env — both easy):**

Option A (recommended, no redeploy needed): Add to Vercel environment variables:
```
NEXT_PUBLIC_CLERK_SIGN_IN_URL=/sign-in
```
Then redeploy (Vercel dashboard → Deployments → Redeploy latest).

Option B (middleware.ts — 1-line change, then commit + deploy):
```ts
// In middleware.ts, change:
await auth.protect()
// to:
await auth.protect({ unauthenticatedUrl: new URL('/sign-in', request.url).toString() })
```

Note: Authenticated users (Mario with active Clerk session) can still access `/dashboard` — this 404 only affects unauthenticated requests.
