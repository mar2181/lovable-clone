### P0/P2 — `/dashboard` returns 404 for unauthenticated users (day 87, since ~June 9)

`GET https://hswebappbuilder.space/dashboard` → HTTP 404 with headers:
```
x-clerk-auth-reason: protect-rewrite, session-token-and-uat-missing
x-matched-path: /404
```

Clerk's `auth.protect()` in `middleware.ts` is rewiring unauthenticated visitors to `/404` instead of `/sign-in`. **Root cause:** `NEXT_PUBLIC_CLERK_SIGN_IN_URL` is not set in Vercel env vars, so Clerk v7 (`7.5.20`) falls back to a 404 rewrite. The page `app/dashboard/page.tsx` exists and the build is clean; this is purely an env-var gap.

Note: signed-in users (Clerk session cookie present) are likely unaffected — Clerk only fires the protect-rewrite for missing sessions. New/signed-out users cannot navigate to the dashboard.

**Fix (Vercel env vars — no repo change needed):**
1. Go to [Vercel project settings → Environment Variables](https://vercel.com/dashboard).
2. Add: `NEXT_PUBLIC_CLERK_SIGN_IN_URL` = `/sign-in`
3. Add (optional): `NEXT_PUBLIC_CLERK_SIGN_UP_URL` = `/sign-up`
4. Redeploy (or wait for Vercel auto-deploy on next push).
5. Verify: `curl -I https://hswebappbuilder.space/dashboard` without a session cookie → expect `HTTP 307` or `HTTP 302` redirect to `/sign-in`, not `404`.
