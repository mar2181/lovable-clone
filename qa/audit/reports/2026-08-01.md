### P0 — `/dashboard` returns 404 (NEW REGRESSION since ~2026-07-24)

`GET https://hswebappbuilder.space/dashboard` → HTTP 404, `x-vercel-cache: HIT`, `age: 723825` (~8 days cached).

Response headers confirm root cause:
```
x-clerk-auth-reason: protect-rewrite, session-token-and-uat-missing
x-clerk-auth-status: signed-out
x-matched-path: /404
```

**Root cause:** `NEXT_PUBLIC_CLERK_SIGN_IN_URL` is absent from Vercel's environment variables. In `@clerk/nextjs` v7, when `auth.protect()` can't resolve a sign-in URL, it rewrites the request internally to `/404` instead of redirecting to `/sign-in`. Vercel's edge cache then locked in that 404 ~2026-07-24.

Route code is intact (`app/dashboard/page.tsx` + `app/dashboard/layout.tsx` both present; `npm run build` produces `/dashboard` cleanly with TypeScript 0 errors).

**Likely trigger:** commit `448b9e8` ("feat(auth): owner-pin by Clerk subject id") on or around 2026-07-14 hardened Clerk auth — possibly removed or changed env vars that controlled the sign-in URL, causing the Clerk protect-rewrite path to activate.

**Fix (Vercel — no repo change needed):**
1. In Vercel project settings → Environment Variables, add (or restore):
   ```
   NEXT_PUBLIC_CLERK_SIGN_IN_URL = /sign-in
   ```
2. Trigger a new deployment (the new env var requires a redeploy; the redeploy also purges the Vercel edge cache).
3. Verify: `curl -s -o /dev/null -w "%{http_code}" https://hswebappbuilder.space/dashboard` → should be 308 (redirect to `/sign-in`), not 404.

**Optional hardening** (repo edit — flag, not auto-applied):
```typescript
// middleware.ts: make the redirect explicit and env-independent:
await auth.protect({ unauthenticatedUrl: new URL('/sign-in', request.url).toString() })
```
