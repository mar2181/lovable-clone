### P3 — Audit tooling broken: `Bearer dev-local-user` no longer works in prod [NEW]

The security fix (`d511723`, ~Aug 9) correctly removed `DEV_BYPASS_AUTH=1` from `wrangler.toml [vars]`. This means `Bearer dev-local-user` now returns **401** in production — correct security behavior, but the audit probe and runbook both use this token to test the build engine E2E.

**Impact:** Build engine E2E, GitHub import live test, and any probe/deep-audit step using `Bearer dev-local-user` against prod are now unauthenticated and will 401. The build engine health is **unknown** this run — only the worker HTTP health endpoint (`/health → 200`) was verified.

**Fix (repo edit — flag):**
The worker already supports `X-API-Key` auth (`auth.ts` lines 45–55, sets `isOwner: true`). Update `qa/audit/audit-probe.mjs` and the runbook to use:
```
X-API-Key: <MCP_API_KEY>
X-User-Id: dev-local-user
```
The `MCP_API_KEY` is stored as a Wrangler secret. Add it to the cloud audit's environment (vault) so the probe can authenticate.
